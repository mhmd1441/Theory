4. SUGGESTED DEMO FLOW

Step 1:
Open the GUI if Qt is available.
If Qt is not available, open the console version.

Step 2:
Create a simple automaton:

States: A B C
Alphabet: a b
Initial: A
Final: C
Transitions:
A --a--> B
B --b--> C
C --b--> C

Step 3:
Test input:

ab

Explain that the machine starts at A, reads a, moves to B, reads b, moves to C, and accepts because C is final.

Step 4:
Show the transition table.
Explain that this table represents the transition function of the automaton.

Step 5:
Analyze a valid pseudo-C program:

int x = 10;
if (x > 5) {
    int y = x * 2;
    return y;
} else {
    return 0;
}

Explain the pipeline:
source code -> tokens -> parse tree -> semantic analysis -> generated code

Step 6:
Show a syntax error:

int x = 10;
if (x > 5 {
    return x;
}

Expected:
Syntax error near token '{'
Expected ')' after condition

Step 7:
Show a semantic error:

int x = 10;
return y;

Expected:
Semantic error: variable 'y' used before declaration.


5. WHAT TO SAY AS A SUMMARY

This project connects Theory of Computation with a practical implementation.
The automaton part demonstrates finite automata and formal language recognition.
The compiler part demonstrates how programming languages are processed through lexical analysis, parsing, semantic checking, and code generation.
The GUI and improved outputs make the project easier to understand, test, and present.
